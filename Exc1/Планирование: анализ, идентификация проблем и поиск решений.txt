Система состоит из трёх приложений:
    Онлайн-магазин — написан на Vue и Java Spring Boot.
    CRM — SPA-приложение, фронтэнд написан на Vue, бэкенд — на Java Spring Boot.
    MES — SPA-приложение, фронтенд написан на React, бэкенд — на C#.

Окружений всего три: dev, release и prod. 
    dev - auto_deploy after unit_test passing and merge
    release - manual deploy
    prod - manual deploy
    
Проблемы и текущие особенности системы:
    - Расчёт стоимости в MES в среднем занимает 2-3 минуты. Скорость расчёта зависит от количества полигонов в 3D-модели. Если модель сложная и детализированная, время обработки может достигать 30 минут.
    - Время обработки заказа от создания до получения результата: ожидание - не больше 3 недель, реальность - несколько месяцев.
    - Постоянные жалобы о неполученных заказах.
    - Производственные мощности работают не полностью и могут обеспечить двукратный рост.
    - Каждый месяц происходит увеличение количества заказов на 100.
    - Долгая загрузка первой страницы MES - список заказов в работе по статусам (дашборд с фильтром). Отображение всех заказов раньше также тормозило.
    - Все сервисы, БД (PostgreSQL) имеют по 1 инстансу и развернуты в Клауде по модели EC2.
    - 2-хнедельные спринты разработки. 1 QA инженер вручную тестирующий release/prod версии - баги уровня high или highest приводят задержкам в релизах. Задержки >= 1 месяц.
    - Есть аутентификация и авторизация везде (проблем нет)

Инициативы по устранению нежелательных ситуаций:
    1. Настроить CI/CD для release/prod окружений. Для этого необходимо нанять еще 1 QA инженера, либо выделить время существующему QA инженеру (урезав время на ручное тестирование при необходимости) на автоматизацию тестирования при деплое release/prod версий совместно с Devops инженером, который автоматизирует оставшиеся этапы CI/CD. Новый QA инженер потенциально будет вручную тестировать текущую функциальность (чтобы не стопорить текущий процесс тестирование release/prod), либо автоматизировать тесты. Сейчас команда разработки добавляет фичу 2 недели, QA тестирует 2 недели, в случае бага возврщает на доработку в очередной спринт - отсюда длительность выкатки фичи занимает >= 1 месяца.
    2. Добавить кеширование в MES по отображению заказов.
    3. Добавить кеширование расчета стоимости для 3d моделей
    4. Добавить трейсинг для обнаружения потенциально наиболее уязвимых точек в системе.
    5. Добавить мониторинг системы - отслеживание состояния каждого компонента и бизнес метрик.
    6. Добавить логирование - быстрое обнаружение узких мест в каждом из компонент.

Приоритет инициатив:
    - QA и devops решают текущую проблемы с медленными релизами. Направлено на решение текущих узких мест.
    - 1 Фронтенд и бэкенд/тимлид разработчики добавляют кеширование. Направлено на решение текущих узких мест.
    - Остальные разработчики (включая архитектора) занимаются добавлением мониторинга и трейсинга, чтобы сделать систему более прозрачной с целью обнаружения потенциальных узких мест в системе.
    - По результатам решения текущих проблем и улучшению прозрачности системы, если выяснится, что система не может справиться с существующей нагрузкой, то рассмотреть разбитие например MES на микросервисы и увеличение ресурсов на проблемный микросервис (горизонтальное/вертикальное масштабирование).
